# 需求文档：close-window-to-tray

## 功能概述

为使用 Niri/Wayland 的 Coding Tools MCP 用户提供可靠的“关闭到托盘”行为：当窗口管理器通过 `Super+Q` 等方式请求关闭主窗口时，只隐藏界面，不退出桌面进程，也不中断 MCP、Actions、Cloudflare 或 FRP；用户可从托盘恢复窗口，并保留明确的真正退出入口。

## 历史经验与坑

- **可复用经验**: 现有 UI WebView 重建流程已经证明，窗口生命周期必须与后台 MCP/隧道生命周期解耦，并通过 `RunEvent::ExitRequested` 防止“最后一个窗口消失即退出”。
- **必须规避的坑**: 不得无条件拦截所有退出事件，否则托盘“退出”无法结束进程；不得在托盘创建失败时继续隐藏窗口，否则用户无法恢复界面；不得把隐藏实现为销毁 WebView，否则会重复触发内存重建和窗口几何恢复逻辑。

## 术语定义

- **关闭请求**: Tauri `WindowEvent::CloseRequested`，包括窗口按钮和 Niri `Super+Q` 产生的关闭动作。
- **关闭到托盘**: 阻止主窗口销毁并调用 `hide()`，后台进程与监听器继续运行。
- **显式退出**: 用户从托盘菜单选择“退出”，允许 Tauri 结束整个应用进程。

## 范围边界

**In Scope（本次要做）**

- 为主窗口创建系统托盘图标，以及“显示窗口”“退出”菜单。
- 拦截主窗口关闭请求；托盘可用且未请求显式退出时隐藏窗口。
- 托盘“显示窗口”菜单恢复、取消最小化并聚焦主窗口；支持托盘点击事件的平台也允许左键直接恢复。
- 保持现有 UI WebView 重建防退出语义，并为生命周期决策补充单元测试。
- 同步应用 patch 版本，构建并安装本机 Linux release 二进制。

**Out of Scope（本次不做）**

- 不修改 Niri 的全局 `Super+Q` 绑定。
- 不新增前端设置项或更改页面视觉设计。
- 不改变 MCP、Actions、Cloudflare、FRP 的启动、停止或认证逻辑。
- 不实现 Linux 多实例治理或开机自启动。

## 需求列表

### FR-1: 主窗口关闭到托盘

**优先级:** Must
**用户故事:** 作为持续运行 MCP 服务的桌面用户，我想在按 `Super+Q` 时只隐藏窗口，以便后台服务和公网隧道不中断。

#### 验收标准（EARS）

1. WHEN 主窗口收到关闭请求且托盘已就绪、未请求显式退出 THEN 系统 SHALL 阻止窗口关闭并隐藏主窗口。
2. WHILE 主窗口隐藏在托盘 THE 系统 SHALL 保持应用进程、MCP/Actions 监听器和隧道监督器运行。
3. IF 托盘初始化失败 THEN 系统 SHALL 不拦截主窗口关闭，避免形成无法恢复的隐藏窗口。

### FR-2: 从托盘恢复或真正退出

**优先级:** Must
**用户故事:** 作为桌面用户，我想从托盘恢复窗口或明确退出应用，以便区分“暂时隐藏”和“停止全部服务”。

#### 验收标准（EARS）

1. WHEN 用户选择托盘“显示窗口”或在支持托盘点击事件的平台左键单击图标 THEN 系统 SHALL 取消最小化、显示并聚焦主窗口。
2. WHEN 用户选择托盘“退出” THEN 系统 SHALL 标记显式退出并结束应用进程。
3. IF 主窗口暂时不存在于 UI WebView 重建窗口期 THEN 系统 SHALL 安全忽略恢复动作，不造成崩溃。

### FR-3: 兼容 UI WebView 重建生命周期

**优先级:** Must
**用户故事:** 作为使用自动 UI 内存释放功能的用户，我想关闭到托盘与 WebView 重建共存，以便既不掉服务也不出现无法退出的进程。

#### 验收标准（EARS）

1. WHILE UI WebView 正在重建 THE 系统 SHALL 继续阻止 Tauri 因最后窗口销毁而退出。
2. WHEN 已发生显式退出 THEN 系统 SHALL 不再用 UI 重建标记阻止退出。
3. WHEN 运行生命周期决策单元测试 THEN 系统 SHALL 覆盖托盘未就绪、普通关闭、显式退出和 UI 重建四类分支。

## 非功能需求

- **NFR-1（可靠性）**: 关闭到托盘不得停止或重启任何 MCP/Actions/隧道运行时。
- **NFR-2（可恢复性）**: 托盘不可用时必须回退为正常关闭，不允许隐藏后无恢复入口。
- **NFR-3（兼容性）**: 使用 Tauri 2 官方 tray/menu/window event API，兼容当前 Linux、Windows 和 macOS 构建目标。
- **NFR-4（性能）**: 窗口关闭决策只使用原子状态与窗口 API，不引入阻塞 I/O。
